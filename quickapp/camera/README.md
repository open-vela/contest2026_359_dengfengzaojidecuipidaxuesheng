本板 `/data` 实测为 tmpfs，照片重启即丢失，不是持久化相册。

该快应用通过桌面运行时的 `system.camera` 原生桥接打开 `/dev/video0`，请求 1024x600 RGB565 帧，以二倍抽样生成 512x300 LVGL Canvas 取景。LVGL 保持运行，不再由相机直接接管 framebuffer。

支持取景、重试、拍照、本次最近照片回看和停止。桌面原有返回按钮负责退出应用。退出时等待采集线程结束，再停止流并释放缓冲区；若底层存储写入阻塞，退出仍可能等待写入结束，此处不承诺硬超时。

照片保存为 `/data/photos/IMG_0000.bmp` 等不覆盖已有文件的 RGB565 BMP，每张 307266 字节。必须已有可写的 `/data` 挂载；应用不会格式化或挂载存储。写入、刷新或关闭失败不会报告成功，并删除本次不完整文件。当前回看显示本次成功保存照片的内存副本，不支持跨启动相册或文件回读。拍照写入期间采集线程暂停取帧，UI 继续运行；不承诺拍照时预览连续或 30 fps。

源码在 `../native/qpk_runtime.c` 和 `../native/camera_photo.h`，界面为本目录 `app.js`。从工作区根执行 `wsl -d Ubuntu-22.04 -- bash camera-app/build-product.sh`，使用今日保留的 Make 构建树增量编译；可传入兼容构建树路径。脚本核对待覆盖运行时，拒绝覆盖未知改动。不是独立干净环境构建，未修改比赛仓或原有发布包。

输出位于 `../product-build/`，包含 ELF、BIN、配置、构建日志和 SHA256SUMS。该配置是 ESP32-P4 v1 测试配置，不适用于未经确认的 v3.2 硬件。尚未烧录。

主机验证：`node --test camera-app/tests/app.test.cjs`；Linux 下使用 `gcc -Wall -Wextra -Werror camera-app/tests/photo_test.c -o /tmp/camera-photo-test` 编译并运行，覆盖 BMP 头、RGB565 字节顺序、非法尺寸和磁盘写满错误。

实板待验：首帧及颜色方向、触摸按钮和返回、写入后独立读取 BMP、缺摄像头与缺存储、100 次打开退出及堆使用趋势、保存中退出、回看返回取景。主机测试不能证明这些项目通过。
