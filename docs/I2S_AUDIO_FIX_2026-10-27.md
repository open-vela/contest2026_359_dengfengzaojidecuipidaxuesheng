# I2S 音频内存错误修复与实板对照

2026-10-27。已修复、完整编译并部署 P4 候选，C6 继续使用已核验的八连接配套固件。设备保持运行；没有提交或推送代码。

## 问题与修复

旧固件在 BLE Host 就绪后，内核堆总量只有 70,528 字节，典型空闲 2,936 字节，最大空闲块约 1,192 字节。PSRAM 用户堆还有十余 MiB，不能用这个数判断内部 DMA 内存是否足够。

实板三轮本地 TTS 对照出现 12 次 `I2S transfer failed: -12`，包含 2,304 字节 TX DMA 副本分配失败；三轮最终均 `result=-5 played_frames=0`。麦克风唤醒线程也出现 `wake_release ... result=-5`。

最终修复包含：

- `glass_music_ui.inc`：音乐页面的歌曲／收藏快照改为按需 `calloc`，退出页面时释放。它是纯 CPU 元数据，不是 DMA 缓冲。分配发生在用户堆已初始化之后；失败先提示并返回，保留旧页面、快照和定时器。内部 BSS 实际减少 **55,648 字节（约 54.3 KiB）**，最终内核堆增加至 126,176 字节。
- `glass_ui_probe.inc`：页面未打开时，音乐搜索结果探针检查快照指针后再访问。
- `esp_i2s.c`：RX 完成复制和缓存同步后，TX／RX 均先释放已完成的 DMA 副本和描述符，再通知上层。回调可能立刻唤醒高优先级生产者；此顺序避免新旧 DMA 分配重叠。先保存回调参数，归还后不再访问可能已复用的容器；I2S 的 APB 引用仍保留到回调返回。
- `glass_music_pcm.h`：播放块为 240 帧／960 字节，保持 64 字节对齐，降低播放与麦克风观察并行时的 DMA 峰值。采样率、声道数据和尾帧对齐规则不变。

DMA 数据和描述符仍使用内部内核堆，没有转移到 PSRAM。真正的分配失败仍上报，不跳过错误或伪造播放完成。

仅修正 DMA 回交顺序、缩小播放块的第一版仍在实板失败，三轮各只播放 480 帧后返回 `-EIO`。该失败镜像 SHA256 为 `7a4668c611d99d1817c51b79e3fadcb0b9e2818941cea56313c6dfddc130767d`；记录保存在 `output/i2s-audio-20261027/fixed.*`。它证明单独处理交接峰值不足以解决内部堆总量与碎片问题，不能将该版记为修复通过。

音乐原生测试首次遇到既有“内置应用”标签断言过期；按当前启动器实际回调注册更新断言后，完整用例通过。原失败日志保留。`checkpatch` 整文件存在既有 CRLF／风格问题；对 LF 规范化检查结果与本次修改行比对，没有新增修改行问题，不宣称整个驱动已完成格式清理。
