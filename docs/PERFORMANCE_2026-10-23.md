## 内存实测

用户堆容量为 20,054,016 字节，即 19.125 MiB。初始短采样的用户堆已用约 10.82 MiB、
可用约 8.30 MiB，仅变化 32 字节；这不是长时间泄漏验收。内核堆另有 132,296 字节，
本次没有缩减 DMA、内核栈或内部 RAM 预留。

`memdump biggest 30` 中最大的两块为：

- 显示分配：可用块 3,686,408 字节，对应 3 × 1024 × 600 × 2 = 3,686,400 字节显示缓冲。
  板级 LCD 按 `LCD_FB_SIZE * LCD_FB_COUNT` 对齐分配，保持不变。
- ESP-TTS“小新”缓存：可用块 3,821,320 字节，载荷头为 `xiaoxin_20221104`，
  与锁定的 3,821,311 字节官方语音文件一致。原实现会在归还后长期保留。

当前固件的 memdump 没有 PID 或分配回溯。memdump 技能的通用解析器无法识别这一精简
格式；本次只按实际地址、大小和开销解析，`heap-top.json` 中缺失的 PID/回溯保留为空。
不能据此为其余分配编造模块归属，也不能把物理 PSRAM 全部算成用户堆。

使用已有的 `desktop speech cache-clear` 安全释放空闲缓存，原有引用保护仍生效：

| 指标 | 释放前 | 紧接释放后 |
| --- | ---: | ---: |
| 用户堆已用 | 11,355,984 字节（10.83 MiB） | 7,567,096 字节（7.22 MiB） |
| 用户堆可用 | 8,698,032 字节（8.30 MiB） | 12,486,920 字节（11.91 MiB） |

实测净减少 **3,788,888 字节（3.61 MiB，约 33.4%）**。该差值包含同时运行的其他线程
分配变化，不等同于语音文件的精确字节数。稍后复查已用为 7,534,360 字节、可用为
12,519,656 字节；后台唤醒请求仍是 20，未被停止。复查单次 CPU 为 34.3%，属于自然
波动，不能归功于尚未烧录的 CPU 优化。

## 源码优化

BLE 常驻任务组的命令 pthread 改为等待带谓词的条件变量，提交命令时唤醒。
没有命令时不再每秒轮询约 100 次；请求副本、截止时间、连接代次和 GAP/GATT 所有权
沿用原逻辑，桌面/NSH 不直接操作 NimBLE 的任务组私有 MQ 描述符。

ESP-TTS 在最后一个使用者归还模型后保留 60 秒，桌面既有循环每秒检查一次并回收。
维护使用 trylock，不等待 SD 加载，不新增线程或 LVGL 定时器；正在借用的模型不释放。
连续播报继续复用缓存。长时间空闲后首次播报需要重新读取并验证 SD 模型，会包含加载
延迟；SD 缺失或校验失败仍明确报错。唤醒模型、识别阈值、采样、音色和音量未修改。
