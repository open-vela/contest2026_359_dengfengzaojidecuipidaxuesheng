# 普通 BLE 与鼠标的互斥切换

最新进展：用户已授权按八台开展自动化，宿主／原生 UI 与独立 P4 ELF 检查结果见 [八设备测试报告](BLE_EIGHT_TEST_2026-10-27.md)。以下“未执行”的文字保留其对应开发轮次的历史状态。

2026-10-27，按用户要求沿用 10 月 26 日的互斥设计：启用鼠标时自动暂停普通 BLE 连接，退出鼠标后自动恢复。此文描述当前源码，不代表设备已经更新。

## 切换行为

- `glass_ble_hid_start()` 先关闭普通连接准入、停止扫描、取消正在等待的 GATT 操作，并请求断开普通连接。确认物理连接结束后才启动鼠标广播。断开失败或等待超时返回错误，不抢占仍在使用的普通连接。
- 暂停会话仍保留原 `generation` 和设备地址，继续计入逻辑会话列表；物理连接数及预留名额按真实连接状态计算。此前多普通设备会话仍保留，但不与鼠标并发。
- `glass_ble_hid_stop()` 在鼠标停止广播且实际断开后，逐个尝试重连暂停设备。关闭鼠标页面也由后台 worker 执行停止与恢复；START 尚未返回时关闭页面，worker 在其返回后继续 STOP，不在 LVGL 回调中等待蓝牙。
- 每次恢复生成新的物理 GAP token，逻辑 generation 保留给原所有者。旧 GAP 回调按物理 token 拒绝，旧 GATT 回包按操作 token 拒绝，不能通过句柄复用修改新连接。
- 用户手动断开、取消恢复或快应用退出时，原所有者可以清理暂停会话，恢复记录随会话清除。控制器 reset 清除全部暂停记录，不跨 reset 重放。
- 对暂停前已加密且已保存配对的连接，恢复连接后请求使用既有安全关系重新加密；状态仍由真实加密事件更新。未配对设备不会因恢复而自动发起首次配对。

## 状态与错误

普通设备页显示暂停状态，鼠标启用或切换期间不再启动普通扫描或新连接；选中暂停设备可“取消恢复”。QPK status 增加全局及每会话 `mousePaused`。`c6ble status` 报告 `mouse_paused`，应用策略的 `mixed_role_capacity` 为 0，不再用控制器连接池容量推断应用支持并发。

恢复每个设备仅发起一次有界连接尝试，连接超时会请求取消。失败返回错误，不无限重试。若暂停失败且物理断开仍未完成，保留暂停记录和准入门禁，可通过再次停止鼠标重试恢复；停止按钮在 host 就绪且无 UI 操作时可用。

恢复范围是 BLE 连接和已有配对的加密请求。扫描、未完成的读写、通知缓存和应用订阅写入不自动重放；应用根据真实连接／加密状态重新发现和订阅。对端关机、超出范围或地址变化，仍可能需要重新搜索。连接成功不等于加密、订阅或业务已经恢复。

## 多普通设备恢复补充

用户随后确认继续完善 BLE 多设备连接。应用上限仍为两个普通设备会话，鼠标与普通设备互斥；不增加控制器连接数，也不根据 ELF 连接池大小扩大硬件能力声明。

最新源码在恢复前固化最多两项 generation，分别记录 `attempted`、`connected` 和 `error`。一个设备的连接失败在收到终态后允许继续恢复另一个设备；一个设备恢复成功不会覆盖另一个的错误。批次内被原所有者取消的连接记录为取消，未尝试的后续项保留 `-EAGAIN`。失败会话按原生命周期退场，后续需要重新连接；已成功恢复的会话及其原所有者保持。

连接等待超时后请求取消，并等待该物理操作结束。若取消仍未取得终态，停止本批剩余尝试，保留尚未恢复的暂停会话，等待显式停止／恢复重试；不在同一控制器上叠加第二个发起请求。

QPK status 增加 `restoring` 与 `restores` 数组，CLI `c6ble central sessions` 输出 `BLE_RESTORES`／`BLE_RESTORE`。设备页区分鼠标暂停和正在逐个恢复。结果中的 `connected` 是该次恢复完成时观察到的结果，实时连接状态仍以 `sessions` 为准；它不代表已完成加密、订阅或应用数据交换。恢复期间发生 controller reset 时，本批结果标记失败；已经完成的批次保留为历史结果。

宿主夹具补写了两台设备均恢复、第一台恢复失败但第二台仍恢复，以及成功设备按原 generation 继续 GATT 的场景。**新增夹具仍未执行，本次也未构建、检查新 ELF 或烧录。**
