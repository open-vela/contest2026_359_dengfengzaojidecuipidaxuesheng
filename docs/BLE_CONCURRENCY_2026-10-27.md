## 已补齐的路径

此前连接池已经映射为 2，但 `glass_ble_role_claim()` 仍以单个 `g_role` 排斥
central 与 HID，两个页面也分别禁止自动扫描/启动，因此连接池容量并未开放给应用并发。

现在使用两个独立角色预留位：一个普通外设 central、一个 HID peripheral。
每位保守预留一个连接名额，扫描、连接中、广播、已连接与正在断开的生命周期均计入；
同一所有者重复 claim 是幂等操作。容量至少为 2 时允许两角色共存；容量为 1 时
仍只接纳一个角色，返回 `-ENOSPC` 而不主动停止另一角色。
这不是任意两个普通外设的多会话实现，也没有通过主机容量推断 C6 实板并发成功。

| 路径 | 源码行为 |
|---|---|
| 先开鼠标再搜索普通外设 | 容量 ≥2 时可保留 HID 广播/连接并启动 central 扫描与连接 |
| 先连普通外设再开鼠标 | 容量 ≥2 时鼠标页可启动 HID；普通连接不被自动取消 |
| 普通设备 GATT/通知 | 沿用单个 central 的 handle、generation、GATT token、通知队列 |
| 鼠标输入/订阅 | 沿用 HID 自己的 handle、epoch、加密、订阅和按键释放条件 |
| 断开任一角色 | 只清除该角色预留位，另一个角色保持原生命周期 |
| 控制器 reset | 两个所有者分别失效；HID 现在也显式释放预留位 |
| 容量不足 | 明确提示“蓝牙连接名额已满”；不抢占、不借用另一角色的句柄 |
| 诊断 | `c6ble status` 增加 reserved_connections、central_reserved、hid_reserved、mixed_role_capacity |

`reserved_connections` 表示应用预留名额，不等于当前已建立连接数。
`mixed_role_capacity` 仅表示编译容量允许应用开放两角色，不是空口或端到端验收结果。
HCI/GAP/GATT 继续由已有常驻 host 任务组的 pthread/事件队列执行，UI/NSH 只提交邮箱。
没有增加第二个 BLE host，没有从短生命周期任务使用 NPL 的 mq 描述符。

## 一并修正的生命周期缺陷

1. central 旧回调先解锁再释放角色，存在新扫描已 claim、旧回调随后将其释放的窗口。
   现在在所有者状态锁内确认完全空闲并释放，claim 同样放在状态锁内且通过校验之后执行。
2. 无效列表下标、过时代次或不可连接广播不会再先占据角色名额。
3. 取消扫描失败原先被忽略并立即显示停止、释放名额；现在保留扫描状态与名额，
   抑制后续列表更新，直到明确取消成功或收到 DISC_COMPLETE。错误返回给调用者。
4. 连接取消和断开错误不再统一吞掉；终止失败仍保留 closing 名额，允许显式重试断开。
5. host 邮箱中的扫描/连接取消带 GAP token，终止带连接 generation 与 handle，
   过时请求在签发前拒绝；显式断开也保留操作开始时的会话身份。
   这增加代次校验，不替代待做的回调竞态与 handle 复用验证。
6. HID 的广播失败、配对窗口结束及 reset 进入空闲后释放自己的预留位，
   不再仅因保留“用户希望启用”策略而占据一个无活动链接的名额。

锁顺序为 owner 状态锁 → host 容量锁。host 容量锁不回调 owner；读 host 状态后先解锁，
再读取 central。新增容量读取不返回设备地址、密钥或配对内容。
