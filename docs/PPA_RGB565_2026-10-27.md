# PPA RGB565 输入与 JPEG 缩小适配

本轮补齐原差距清单第 6 项的 RGB565 输入。代码、自动化回归与构建分别记录；
不把宿主寄存器替身或软件像素结果当成真实 PPA 像素验收。
候选构建完成后只保存制品，不自动部署，也不发起个人测试请求。

## 接口与行为

| 接口/路径 | 本轮行为 |
|---|---|
| `P4_PPA_SRM` | 保留原命令及 `p4_ppa_job_s` 布局，输入仍为 packed UYVY，输出 RGB565 |
| `P4_PPA_SRM_RGB565` | 新增独立命令，输入为 P4 原生小端 RGB565，输出 RGB565；不启用字节/RGB 交换 |
| 驱动几何 | 仍限定 2..1280 × 2..720、1/16..1 倍，缩放步长 1/16；RGB565 不再受 UYVY 的偶数宽度限制 |
| SDK 块配置 | 继续使用官方 `ppa_ll_srm_get_dma_dscr_port_mode_block_size`；RGB565 为 18×18，UYVY 为 20×18 的 16×16 宏块输入边界 |
| 用户态适配器 | `qpk_ppa_rgb565_scale` 校验精确等比缩小，复制有行步幅的输入到私有 128 字节对齐 RAM；成功后才复制到调用方 |
| JPEG 链路 | `qpk_jpeg_hw_decode_scaled` 先解码到私有 RGB565，再交给 PPA；JPEG ioctl 退出、释放 DMA2D 后才获取 PPA 所有权 |
| 正常 JPEG 缩小 | 非裁剪的 JPEG decode/region 路径可在精确比率下尝试硬件缩小；原有全尺寸接口继续可用 |
| 失败处理 | 设备不存在、资源不足、硬件失败或不支持比率时，保留原软件解码路径；PPA 失败不会提交半帧 |
| 背景/步幅 | 成功后只填充图像与 letterbox，不改输出行尾 padding |
| 实时预览 | `decode_view`/裁剪滤镜路径保留原软件采样策略，不进入新增 PPA 缩小分支 |

底层仍要求源/目标为合法、互不重叠的对齐 RAM；高层适配器通过私有副本允许调用方源/目标别名。
每次调用的所有私有内存和 FD 都在返回前释放，不新增驻留线程、连接、日志正文或 Flash 写入。
输入范围及尺寸限制在分配前检查；内存不足时返回错误供软件路径处理。

## 同时修正的错误处理

旧驱动只检查图像缓存同步结果，没有检查两次 DMA 描述符 C2M 的返回值。
现在任一同步失败都在启动 DMA 前返回 `-EIO`，不会使用未成功同步的描述符。
输出 M2C 仍在双向 DMA 停止后执行，其失败不会触发高层输出提交。

ioctl 现在只快照一次小型 job，随后在等待共享 DMA2D 和执行期间使用该副本，
避免已经校验的尺寸/地址字段被并行调用方更改。这是本板 FLAT 构建的同步接口；
调用方仍须持有输入/输出缓冲直至返回，不提供跨保护域用户地址复制机制。

## 自动验证

- 实际 PPA 函数体加官方 SDK 块计算函数：旧 ABI、新 RGB565 模式、奇数 RGB 宽度、
  错误形状/对齐/RAM/重叠、四个 C2M 失败点、job 快照、超时和描述符错误后的恢复。
- 实际 PPA/JPEG/MJPEG 适配器：精确比例、输入/输出步幅与别名、私有 DMA、失败不提交、
  正常缩小、letterbox、真实软件回退、预览分支隔离和 FD 释放；ASan/UBSan。
- 原 JPEG 适配器、共享 DMA2D 管理器、相册、相机缓存/scanout、GUI 交接边界与 MJPEG 预览回归。
- P4 交叉编译已通过 DMA2D、PPA、JPEG 解码/编码四个驱动单元。

新增测试中的设备 peer 只校验传输、地址和生命周期，不模拟并证明真实 PPA 插值、颜色精度或性能。
初始测试夹具的 API 参数错误、未使用 SDK 参数告警及记录变量同名问题均已修正，失败记录保留在输出目录。

## 本轮范围外

ARGB8888/RGB888、旋转、镜像、混合、填充、任意比率与放大仍未在应用层开放。
没有更新 C6、SDIO 时钟、BLE 容量、数据分区或安全配置。
稳定下载 5 Mbps 的验收继续保持 `skipped_by_user`，本轮未测速。
