# 复杂环境音误唤醒排查 · 2026-10-22

用户报告旁人、电视或短视频声音触发唤醒，随后可能被转写并进入 AI 接话；设备自身当时没有播放音频。
本轮只读核对设备仍运行 `f45999a6…`，未重启、烧录、采集麦克风或改动浏览器。

## 复现与原因

冻结的合成开发语料中复现两个错误：10 dB 加性噪声下的“我喜欢 OpenVela”，以及回声下的“请不要唤醒设备”。
两者均在正常 640 ms 端点被接受，不属于 4 秒强制截断分支。

旧判定只比较最近三个正／负模板的 DTW 距离比。即使输入与所有正模板都较远，只要负模板更远，比值仍可能通过。
上述两个误判的平均正距离约为 0.965 和 1.004，而通过判定的正常开发样本最高约为 0.735。

## 源码修正

新增 `glass_wake_ratio_distance()`，在原有一次 198 模板 DTW 搜索中同时返回正模板绝对平均距离；旧 `glass_wake_ratio()` 保持数值兼容。
生产唤醒还需满足绝对距离不大于 0.95，原模型、认证摘要、相对门限、320／640 ms 端点、冷却与音频所有权均保持不变。
NuttX 下仅在该条件拒绝原本会通过的候选时输出数值诊断，不记录音频或转写正文。

包络仅用六个原训练声线的正样本估计：364 个原本接受的训练场景中，最大平均正距离为 0.609958。
保留 50% 余量并向上取整到 0.05，得到 0.95。该包络绑定当前认证模型，更新模型或特征后需要重新校准和对照。
验证／测试语料已用于历史开发，不能称为未触碰的最终验收集。

## 复现

在 Linux／WSL 的既有语音开发环境中使用 GCC 和 NumPy。
`--reference` 指向修改前冻结的桌面唤醒源码目录；需包含 `glass_custom_wake.*`、`glass_wake_features.*`、`glass_wake_model.h` 和 `qpk_espdl_sha256.c`。

```sh
python3 tools/test_wake_distance.py --output out/wake-distance
python3 tools/test_wake_distance_replay.py --reference /path/to/reference --corpus /path/to/corpus --model /path/to/nihao_openvela.gkw --output out/wake-distance-replay
python3 tools/test_speech_barge.py --output out/wake-barge
python3 tools/test_wake_handoff.py --output out/wake-handoff
```

回放工具不训练模型、不访问网络或设备；输入 PCM 按语料清单核对摘要，正负样本使用相同的固定声学变换。
