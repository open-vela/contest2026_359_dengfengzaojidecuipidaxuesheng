## 后续源码补齐：P4 适配器诊断

候选 12 的 `c6probe netstat` 仅读取本地 P4 计数，不执行 C6 初始化、RPC、CMD52/53、
复位或联网动作。STA/AP 分别记录 TX 通知数、轮询次数、Hosted 接纳的包/字节、发送错误和最后错误、
AP 关闭期间发送拒绝、最大 Hosted 发送耗时，以及 RX 包/字节、入口不合法、接口未就绪和不支持协议数。
`tx_send_max_us` 包含 Hosted 调用内锁等待和发送，但不能再拆分为信用/总线等待，也不是空口发送耗时。
成功发送计数表示 Hosted 接纳，不代表无线 ACK；RX 数包含送入协议判断的帧，可能另被记为不支持协议。

计数器为本次启动累计的 32 位无符号数，回绕差值按模 2^32 计算；字节计数在持续流量时也会回绕。
每项采用原子访问，读取快照不暂停流量，因此各字段不保证来自同一瞬间。
未增加统计清零接口，避免诊断动作破坏前后对比。时间采用单调时钟微秒差值，只统计完整发送调用。
读取 API 与 netdev 的可重置对象分离，不为诊断获取网络、连接或 Hosted 总线锁。
本轮实际 STA/AP 入口、发送错误、独立计数、只读无 RPC 及回绕宿主回归通过；
异步 TX 锁死负控制也通过。未改变 10 ms 调度或 20 MHz SDIO，未声称 5 Mbps 或 CRC 回归已解决。

## 测量方法

`tools/network_benchmark.py` 和配套 HTML 提供同源浏览器测试。
固定 4 MiB 随机 payload 在 RAM 中生成、接收及校验，开发板不写 Flash。
HTTP 禁用缓存和内容转换。上传和下载顺序分别测试：10 秒预热，再做 3 次至少 60 秒窗口。
每次 4 MiB 数据都必须完成 CRC32 校验；浏览器和服务端有效字节数、请求数必须一致。
请求失败、错误 CRC、错误窗口/方向、服务端写入失败、伪造统计都不能使该窗口通过。
浏览器可主动停止，失败后不自动重放整轮测试。

报告接收端完整有效字节除以客户端/服务端两者较长单调时钟耗时的 HTTP 应用吞吐。
同时保存原始客户端速率与两端耗时；服务器计时含窗口开始/结束控制往返，作为较保守的主报告值。
窗口包含请求间隙和客户端 CRC 校验成本，单独记录校验耗时；它不是纯 TCP 容量或无线 PHY 速率。
每方向只允许一个 payload 请求同时进行，另有一个低频并发延迟请求，记录 RTT p50/p95/p99、
超时次数和窗口结束时被取消的未完成探测。预热不进入中位数和范围。
服务端独立单调时钟限制客户端不能报告更长于服务端 1 秒以上的耗时；
高延迟的控制往返可以使服务端更长，主速率使用较长计时，不将有效慢连接仅因差值超过 5 秒而拒绝。
最后一个完整 payload 可以使窗口超过 60 秒，必须报告真实时长。

仅保存有界统计 JSON 与源码 SHA，不保存 HTTP 正文、payload、配置凭据或页面会话密钥。
线程最多 8 个，6 轮完整测试上限，单请求/窗口/服务都有边界。
4 MiB 响应按 64 KiB 分块写，单块等待与整响应截止分开，keep-alive 等待能覆盖低速响应排空时间。
当前测试不包含多连接吞吐、同时双向、UDP、纯 Wi-Fi/纯有线参考、20 次开关及长期容量矩阵。
P4 CMD53/信用等待/调度内部统计和实际以太网速率/双工尚未补测；不能仅凭本轮吞吐断定瓶颈。
