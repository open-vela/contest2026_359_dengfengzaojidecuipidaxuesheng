# 八连接 C6：HCI 长度校验与离线压力测试

2026-10-27。继续完善 C6 八连接配套候选，保留“不烧录”的要求。本轮没有设备串口、复位、烧录或无线操作。

## 已修改

固定 Hosted 的 `process_hci_rx_pkt()` 原先直接补回 H4 类型字节后转交 SDK，没有检查命令／ACL 头声明的长度是否与收到的长度相等。固定 SDK 的 `hci_driver_vhci_host_tx()` 命令路径随后按实收长度执行 `memcpy`，没有在这一层核对命令参数长度。

在 Hosted 边界新增 `openvela_hci_payload_valid()`：

- 命令须至少有 3 字节头，实收长度等于参数长度加 3；覆盖零参数至 255 字节参数边界。
- ACL 须至少有 4 字节头，实收长度等于小端数据长度加 4；连接 handle、PB flags 和数据内容保持原样。
- 拒绝空指针、短头、未知的主机到控制器类型，以及补 H4 字节后会溢出的长度。
- 当前 P4 BLE 配套只接纳主机到控制器的 Command／ACL；不新增 SCO／ISO 支持。控制器到主机的事件仍走原回调。

拒收发生在 SDK 分配／复制前，不截断数据、不自动重发，也不伪造命令完成回执。正常帧保留原 SDIO／VHCI 路径和内存归属。没有修改 SDK、连接调度、队列配置、分区或已有 Wi-Fi／SDIO 修复。

`tools/prepare_c6_hci_frames.py` 提供带完整性校验的幂等变换；当前 `prepare_c6_ble_capacity.py` 会一并应用它。`tools/test_c6_hci_frames.py` 从实际生成源码提取函数，并提取固定 SDK 的真实 host-TX 复制函数验证。

## 实际测试

| 项目 | 结果 |
|---|---|
| 旧路径负对照 | 在固定 260 字节命令分配桩下，旧路径复制 1,023 字节时 ASan 报 `heap-buffer-overflow`；修正后同一输入在进入 SDK 前被拒绝 |
| 控制器到主机 | 八个合成连接标识、八个生产线程交错，共 8,000 帧；消费后逐字节／逐连接顺序校验，原借用缓冲可立即改写 |
| 主机到控制器 | 八个连接标识轮流交错，共 8,000 个 ACL 帧，经真实 Hosted 处理函数和 SDK 复制函数，数据及连接标识保持 |
| 队列与内存 | 受控队列峰值 20；回调分配失败、队列在接纳前拒收均按预期处理；候选压力例分配／释放均 16,003 次、存活数归零 |
| 格式边界 | 325 个短帧／类型组合，另有空指针、长度溢出、超长命令和命令两端边界检查通过 |
| 新旧正常路径 | 旧版与新版正常帧压力均通过；候选 ASan／UBSan 无错误，旧版超长命令负对照按预期失败 |
| 初始化 | 对本轮实际源码再次运行容量初始化及错误／负配置回归，通过 |
| 完整构建 | 独立 C6 交叉构建、esptool checksum／附加 SHA、分区和最终 ELF 检查通过 |

这里的 SDK 函数真实，但命令分配器、mbuf、队列和控制器 forward 为受控宿主桩。260 字节分配模型不是对实板控制器内部堆布局的测量；这些结果不作为历史监督超时 `520` 的唯一根因证明。
