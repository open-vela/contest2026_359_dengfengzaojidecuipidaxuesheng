# 米家 HA Mushroom UI 素材库

本文记录米家 Home Assistant 首页的视觉组件、状态语义和参考编排。示例名称与数值
只用于设计预览；固件页面必须显示 Home Assistant 返回的真实实体名称、状态和单位。

## 视觉基础

- 页面底色：浅灰白；功能单元为纯白卡片，使用极淡灰色描边或轻微阴影。
- 卡片圆角：约 8 px；卡片之间保留稳定间距，内部留白充足。
- 内容结构：分组标题下使用流式网格，同组卡片尽量等高。
- 标题使用常规字重；数值放大；辅助状态使用较小的浅灰文字。
- 激活的灯和开关使用暖黄色；关闭和不可用状态使用灰色。
- 温度、电压使用橙色；天气和降雨使用蓝色；卷帘使用紫色；能源正向值使用绿色。
- 图标优先使用简洁线性或面性图标，布局统一为“图标 + 名称 + 状态/控件”。

## 顶部状态胶囊

蓝色导航栏下方放置三个白底、细灰边框的椭圆胶囊。胶囊左侧为图标，右侧为
数值与单位。参考内容：

| 类型 | 图标 | 示例 |
| --- | --- | --- |
| 温度 | 温度计 | `10.5 °C` |
| 湿度 | 水滴 | `70.4%` |
| 在家状态 | 小车/住宅 | `Away` |

## 通用卡片组件

### 状态卡

用于灯、卷帘、门窗、媒体设备、移动侦测、更新等实体。左侧图标表达域和激活状态，
右侧第一行显示名称，第二行显示状态或数值，例如 `Open · 100%`、`Playing`、
`Up-to-date`。

### 数值卡

用于温度、湿度、照度、电压、功率、充电量和碳强度。名称与图标位于顶部，主要
数值使用大号文字，单位紧随数值但保持较弱层级。

### 亮度卡

用于支持 brightness 的灯实体。顶部显示灯图标、名称和百分比；主体为横向圆角
进度条，暖黄色填充表示当前亮度，浅灰色轨道表示剩余范围；底部可显示辅助状态。

### 温控卡

用于具有目标温度的 climate 实体。顶部显示名称和运行模式；底部为
`− 21.0 °C +`，减号和加号各自使用独立圆角按钮，中间显示目标温度。

### 趋势卡

用于温度等历史数据。数值下方绘制无边框、无坐标轴的迷你折线，仅表达趋势；
温度曲线使用浅米色或与状态色一致的低饱和色。

## 参考分组

以下分组用于制作预览、占位数据和组件覆盖测试。真实页面应根据 HA 区域与实体数据
生成分组，不能把这些名称硬编码为用户设备。

| 分组 | 参考实体与组件 |
| --- | --- |
| Study | Spotlights 49% 亮度卡、Floor lamp 70%、Shutter、Nest Hub；标题胶囊 `In a meeting` |
| Outdoor | Door light、Flood light、Temperature 趋势卡、Motion、Illuminance |
| Climate | Sun、Rain、Downstairs 温控卡 |
| Kitchen | Shutter、Worktop、Fridge、Voltage、Nest Audio、Spotlights 100% 亮度卡、Upstairs 温控卡 |
| Living room | Meeting mode、Bar lamp、Desk、Blinds、Nest mini；标题旁显示温湿度 |
| Energy | EV、Last charge、Home power、Fossil fuel、CO2 Intensity |
| Updates | Auto-update、OS |

## 数据绑定规则

- 名称、状态和单位来自 HA 实体；`unavailable` 与 `unknown` 必须明确显示，不伪造数值。
- 灯的亮度来自 `brightness`，换算为百分比；没有亮度属性时退化为普通状态卡。
- 温控加减控件仅在原生服务允许对应控制动作时显示，否则使用只读状态卡。
- 迷你趋势图需要历史数据；只有当前状态时不得生成虚假波形。
- 房间分组依赖 HA 区域/设备注册表。仅有 `/api/states` 时使用域或用户收藏分类，
  不依据名称猜测房间。
- 控制成功仍以回读实体状态为准；HTTP 2xx 不能直接当作设备已执行。

## 小屏适配

- 800×480 以三列内容为基准，每屏显示六张设备卡。
- 空间不足时依次减少列数，保持文字和控件不重叠；不缩放字号来强行塞入。
- 顶部状态胶囊和分组标题可横向分页，但设备控制区域必须保留稳定触控尺寸。
- 分组、分页、搜索和收藏只改变展示集合，不改变连接、刷新或控制确认逻辑。
