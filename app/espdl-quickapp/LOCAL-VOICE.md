# 本地语音 APP

本模块是 ESP32-P4 / openvela 的原生 LVGL 应用。默认本地对话只输出文字；V2 朗读、离线转写和唤醒均按用户实际使用准备资源。开机与进入 APP 不自动安排模型检查或加载。离线中文转写已有公开样本板上验证，真人语音及声学效果仍需验收；本地入口不会调用云端转写。原助手保留手动入口。

## 资源与构建

默认 SD 路径是 `/sdcard/local-voice/models/edgeidiot-sft2-baker-v2-20261031/`。固件只包含推理代码与界面。`tools/local_voice/export_models.py`、`export_frontend.py`、`prepare_wake.py` 从确认的输入导出权重及字典；`finalize_package.py` 最后生成 JSON 清单和 `GLV1` 二进制清单。每个文件保存字节数、SHA-256，运行时 ABI 为 1。

`build_bilibili_v3.py --local-voice-sdk <prepared-sdk>` 显式启用应用，须同时使用原有 `--speech-runtime`。它从最终 NuttX 配置获取 SDK 编译参数，将外置权重的 EON 算子编译成独立库。继续执行原有 BSS、分区、XIP、重启闭包检查，不更改应用偏移或数据区。

资源包组成：

- `edgeidiot/`：SFT2 的 Q4 分块权重、张量目录、NFKC / ByteLevel BPE 词表与原聊天模板。
- `tts-v2/`：固定 `student_acoustic_spectrum.pt` 的 Q8 权重、张量目录、中文前端和来源记录。
- `wake/`：原三分类 SDK 的 7,776 字节训练常量。
- `notices/`、`checks/`：来源与第三方声明、分词和发音用例。

不要将模型复制到内部 Flash。缺卡、损坏、版本不符和读写失败均返回错误。推理中的 SD 读取错误还会撤销模型就绪状态，成功检查资源后才能恢复后台唤醒。安装器只创建新的 SD 版本目录，先上传临时目录，最后重命名；现有模型和用户内容保留。

## 执行与音频所有权

`glass_local_voice_start()` 仅在常驻桌面任务初始化。UI / NSH 通过有界请求入口提交工作，不能创建脱离短生命周期任务组的音频线程。

文字对话依次执行：仅校验大模型相关资源 → 分词 → Llama → 释放 LLM / KV → 保留文字回答。此路径不打开 TTS、ASR、唤醒文件或音频设备。“朗读回答”和“文字朗读”才执行 TTS 资源校验、中文前端、V2 合成及 24 kHz 播放；TTS 只额外使用共享的 NFKC 字典，不需要 LLM 权重。LLM 最高上下文 512 token、最多输出 96 token，沿用原包的贪心、重复惩罚 1.15 和禁止重复 4-gram。预填充每批最多 32 个 token，保持逐列 FP32 累加顺序；本轮已校验的权重流只在本轮复用，退场后全部关闭。上下文不足时丢弃最旧的完整历史轮次；单条输入过长或内存不足时明确拒绝。

“语音输入”首次使用时在后台检查 ASR 资源，通过后才取得麦克风；取消或关闭录音页面也会取消仍在准备的录音请求。唤醒开关关闭时不创建唤醒模型。开启后，监听器独立校验其自己的权重，无须先加载对话、TTS 或 ASR 模型。显式“完整检查”是诊断操作，会检查所有模型；普通对话和进入页面均不调用它。

推理分配最多 12 MiB，并检查当前可用内存、连续块；每次目标分配继续保护 4 MiB PSRAM 余量。可用预算较低时，V2 使用同一份 Q8 模型按行从 SD 读取并减小声码器分块，不换声音或算法。界面和音频结构仍由原有服务持有。

合成输出以有界分块保存在 PSRAM，完成后释放模型，再以原生 24 kHz 连续播放。音频分块与推理工作区共同计入 12 MiB 上限，每次分配继续保护 4 MiB PSRAM 余量；缓冲不足返回内存错误，不写临时音频到 SD 或 Flash。正常结束、停止和错误都会释放分块。保留整句统一峰值增益、144 ms 分段停顿和 125 ms 起始留白。通用 C 声码器仍需实测速度与扬声器验收。

麦克风继续通过原有音频所有者、后台唤醒让出和 DMA 回收协议管理。只有一个 EON 实例；另一个创建请求返回忙。选中本地目标时，全局事件只打开本地 APP，不进入旧云 ASR 路由。其他前台音频占用时让出，释放后恢复待机。播报阶段只支持触摸停止，不宣称已支持语音打断。

## 接口与内容保存

`glass_local_voice.h` 提供发送、停止、检查、状态读取、新对话、显式保存和唤醒目标切换。状态含请求 ID、阶段、回答、错误、内存峰值、首 token / 首音及总耗时。旧请求清理完成前不会接纳新模型请求；取消中的迟到结果不能进入新会话。

全局唤醒开关与目标选择分开：开关关闭时停止监听，目标可独立选择本地 APP 或原助手。两者是基础配置，保存于内部 Flash `/data/config/local-voice-wake`；新配置默认关闭唤醒、目标为本地 APP，已有用户设置继续生效。改变前走统一 AI 静默屏障；内容相同时不写入。会话默认只在内存；“保存会话”才写入 `/sdcard/local-voice/sessions/`，缺卡不回退 Flash。播报缓冲只在内存，显式会话文件才写 SD。

系统设置侧栏也提供“本地语音”页，可打开或关闭全局唤醒、在本地 APP 与原助手之间切换、检查 SD 模型。它与 APP 共用后台配置服务；设置保存或模型任务进行时禁用重复提交，保存失败保留原选择。切页只释放设置控件与定时器，不关闭后台待机。读取失败的模型错误独立保留，切换唤醒目标不会清除它；成功检查模型后才恢复就绪状态。

本地模型仅生成文字与声音；没有 Agent、MCP 或家居工具入口。

诊断命令（服务必须已由桌面初始化）：

```
desktop local-voice status
desktop local-voice check
desktop local-voice read "你好。"
desktop local-voice chat "你好"
desktop local-voice stop
desktop local-voice new
desktop local-voice save
desktop local-voice wake local
desktop local-voice wake assistant
desktop local-voice wake off
desktop local-voice wake on
```

状态诊断不打印对话正文。选择原助手意味着恢复原助手的既有行为；本地 APP 本身始终离线。

## 验证边界

`verify_engines.py` 验证真实 C 分词、Q4 Llama 和 Q8 V2 与原工具链参考。`verify_v2_ten.py` 保存同句 FP32 / Python Q8 / C Q8 的音频，量化导致的时长变化单独记录，不用时间拉伸隐藏差异。`verify_service.py` 测试真实模型的取消、旧请求、低内存、损坏、目标切换和音频回收；硬件是替身。`verify_wake_adapter.py` 测试原 SDK 与真实适配器的单实例、复位、拔卡和释放。

主机数学一致、固件链接、烧录读回、实屏、真人唤醒、音质和速度必须分别记录。测试音频检出不能代表真人准确率。

首个 ASR 候选仍为官方中文 Zipformer 14M（2023-02-23）。原 INT8 初始化权重合计 24,738,169 字节，现成 ONNX 驻留路径不适合本板，但流式状态能够容纳；不能据此宣称整个候选不可行。

`experimental/` 已实现独立 C 的 16 kHz 特征、固定形状图执行、显式状态、按行 SD 布局 Q4/Q8 解码、encoder/decoder/joiner 贪心循环和中文词表。前馈使用 Q4，敏感层使用 Q8；常量、计划和词表全为外部模型资产。三个连续状态块与 ONNX 参考对照通过，两段官方 16 kHz 语音在完整 C 路径下均与同精度 sherpa 参考文字一致。主机追踪峰值约 3.09 MiB（包含 C PCM/输出及工作区，不含 libc FILE 元数据），不能替代板上总堆、连续块和 4 MiB 预留实测。主机 ASAN/UBSAN 已覆盖完整识别器取消、低内存、回调失败、重入、重复运行、损坏计划和词表。

这些代码尚未加入候选 7 的构建，独立实验模型包也未覆盖已验收的 SD 版本。下一步是常驻后台服务、资源清单验证和唯一麦克风所有者接入，再完成最终固件链接、板上中文转写/取消/内存和真人质量验证；通过后才能启用 APP 语音入口及全局唤醒完整链路。当前固件继续显示“离线转写未就绪”，不得将固定指令识别当成自由中文转写。测试与来源细节见 `experimental/README.txt` 和 `experimental/ASR-SOURCES.txt`。

2026-10-31 板上阶段更新：`--local-asr-evaluation` 已把完整 C 运行时与 SD 样本任务加入常驻服务。候选 8 的触摸停止通过，但完整样本因 SD 数据令牌超时（ff）返回 `-EIO`，未记作转写通过。候选 9 保持相同模型和逐元素累加顺序，使用顺序缓冲读取、共享权重矩阵合并批次，以及最多约 1.92 MiB 的 packed joiner PSRAM 缓存；模型仍存 SD，不写 Flash。主机全部三图连续状态输出与候选 8 逐位相同。

候选 9 两段官方 16 kHz 样本在 P4 分别用时 517,180 / 506,250 ms，25 字中文都与参考一致；追踪峰值分别为 5,253,453 / 5,238,783 字节，采样空闲 PSRAM 最低 6,379,952 / 6,378,824 字节。触摸停止约 0.98 秒，随后实际 EI 推理恢复；临时改变的全局唤醒配置已恢复。镜像独立读回和数据分区保持检查通过，内核配置与候选 7 相同。它仍是较慢的文件样本验证候选，不是实用速度或任意 SD 故障已根治的声明。

原生诊断：`desktop local-voice asr-test 0` / `asr-test 1`。只读取清单约束的官方样本，不连接麦克风；`asr_ready` 继续为 false。新增的 `glass_local_capture*` RAM 采集/原有音频适配代码已通过主机资源测试和真实 NuttX RV32 对象编译，但未链接进候选 9，仍须接到请求/取消/页面/全局唤醒后再做真人、DMA、音质、拔卡及完整链路验收。


## 候选 11：麦克风与完整本地模型链路接入

本地对话页新增语音输入、结束录音和音量条。本地唤醒事件只路由到本地 APP；未就绪时仍明确显示离线转写未就绪，不调用腾讯云。单一常驻工作线程依次执行 RAM 采集、Zipformer、EdgeIdiot 和 V2；采集退出后归还 DMA/音频会话，转写退出后关闭全部图/缓存并释放 PCM，再调用原有 LLM -> 释放 -> TTS 流程。

录音默认静音 1.5 秒结束、无有效语音约 8 秒退出、最多 60 秒；到上限整段失败，不把截断语音当作完整输入。结束录音绑定 request ID，旧请求不能结束新录音。离开页面会取消本页仍在排队或进行的录音；已经开始的模型工作留在服务中，可重新打开查看并停止。

真实模型主机测试（ASAN/UBSAN，采集、播放和卡状态为替身）已通过：官方 16k 样本经同一 PCM 接口输出 25 个 ASR token，与既有参考 FNV 04bc9ea5 一致；EdgeIdiot 生成 57 token，V2 合成并提交 566712 帧 24k PCM。追踪峰值 11776081 字节，整条链路 379183 ms，首音频提交 379175 ms；同时运行了构建，不能把这个数作为独立性能基准或声学首音。无真实扬声器输出。

此前候选 10 的主机串联因回答包含 AI 而在 V2 前端返回 ENOTSUP，未烧录。候选 11 用原有中文字典拼读 ASCII 字母，独立 AI 规范为“人工智能”，显示文字/历史不修改。新增 52 个大小写字母用例、边界和 NFKC 测试；十句既有中文的发音序列逐项完全相同，声学/声码器代码和 SD 模型字节保持原值。不把中文字母拼读标记为英文声学支持。

资源测试覆盖录音取消、结束/迟到结束、新会话、ASR 取消、准入、缺卡、损坏、OOM 和旧请求；原有语音/配置四项回归及文字朗读回归通过。原生 LVGL 页面验证深浅色、音量条、文字回填、切页生命周期、唤醒只触发一次及键盘不启动云录音。候选 11 完成链接/XIP/分区/复位/热点检查，新 BLE 身份 C3:0D:9C:4D:FB:1F。

原始模型、SD 文件与 4 MiB 数据分区保留。部署与原生短采集结果以 output/local-voice-20261031/device-flash11/DEPLOYMENT.json 和 device-microphone11-r5/BOARD-MICROPHONE.json 为准。用户当前暂时无法确认实屏/背光；真人中文端到端、扬声器听感、真人唤醒/误触发、冷启动、拔卡和新 BLE 配对仍未验收。候选 9 的两次实板样本转写约八分半，当前仍属慢速验证阶段。长回答还须核对实板可用预算，资源不足会明确拒绝，不以主机 12 MiB 预算替代实板的 4 MiB 余量检查。


## 候选 12：模型检查取消与转写异常提示

复现并修正候选 11 的检查回执问题：在 ASR 资源 SHA 校验时停止，旧代码的 asr_error 已为 ECANCELED，但整体 error 被保留为 0。候选 12 传播停止与介质错误，追加 GLV_CHECKING_ASR 阶段；缺失/损坏/暂时内存不足的 ASR 包仍独立报告，保留已经通过的文字模型就绪状态。对话与设置页现在显示实际生产错误文案和“文字功能可用”，检查进行中不显示旧错误。

主机 ASAN/UBSAN 的真实常驻工作线程 + 基础包 SHA、ASR 检查故障替身验证取消/旧请求/缺包/损坏/OOM/介质错误/恢复；原问题先失败再修复通过。实际 LVGL 用生产错误函数验证文案、控件可用性及原麦克风/键盘/切页回归，四项配置/语音回归通过。

候选 12 已完成 ELF/XIP/复位/分区检查、烧录、独立镜像读回和 4 MiB 数据分区原样校验。真实 SD 校验阶段实板停止返回 -125，基础模型仍就绪而 ASR 暂未就绪；重新检查后两者均恢复。证据：device-resource-check12/BOARD-RESOURCE-CHECK.json。未采集或播放音频，实体屏幕/背光不计作通过。

编译输入只改变 glass_local_voice.c 的检查分支、公共阶段枚举和 UI 提示。其余服务字节、麦克风、ASR/LLM/V2 数值代码及其模型资源保持候选 11，不重新标注过去的模型与麦克风实测为候选 12 的真人测试。用户当前的真人语音验收可用性问题仍等待答复；真人唤醒/误触发、中文完整链路、扬声器听感、实屏、冷启动、物理拔卡及新 BLE 配对未完成。


## 候选 13：请求归属与新会话隔离

主机先复现两个问题：模型检查把上一轮转写以新请求 ID 返回，可能覆盖编辑中的输入；新会话在旧引擎仍忙时继续公开旧回答和转写。候选 13 为转写保存实际 owner request，检查/保存不重新标记；新会话立即清空，并在同一互斥锁内拒绝取消后的 token、最终文本、转写和音量发布，旧资源退场前保持 busy。实际模型数值代码、采集/DMA 与其他固件输入未改变。

确定性迟到引擎、已有旧历史、新会话立即清空、检查/保存不回填以及实际 LVGL 编辑保留测试通过；真实全 C 模型再次完成 25 ASR token -> 57 回答 token -> 566712 帧 24k PCM，主机追踪峰值 11776081 字节，380828 ms（并行构建期间，不作独立基准）。四项回归和旧服务测试通过。

候选 13 已烧录并独立读回，4 MiB 数据分区原样保留。首次原生测试在启动 SHA 校验 tts-v2/weights.bin 时出现 mmcsd data token ff、-EIO；未派发文字推理。界面正确显示失败并撤销就绪状态。一次显式只读检查恢复了所有资源，SD-FAILURE13.json 保留失败，不宣告传输根因已修复。

恢复后的实板文字推理产生真实部分回答，首 token 150571 ms；随后“新对话”约 1.21 秒清空并退场，reply bytes=0/FNV811c9dc5、无音频提交，最后再次检查模型通过。证据 device-new-session13-recovered/BOARD-NEW-SESSION.json。用户已选择稍后再测真人语音，本轮没有启动麦克风。实屏/背光、真人唤醒/误触发、真人中文完整链路、听感、冷启动、物理拔卡和新 BLE 配对仍未验收。

SPI3 20MHz、通用读写重试 0 为当前保留配置；驱动 SD_READACCESS 默认 100ms，实际 slot 时限待诊断记录确认。偶发 SD 读取故障的根因仍未定位；不能直接开启同时影响写操作的通用重试来掩盖。后续稳定性工作应先记录数据令牌等待的实际时长和轮询次数，保持写路径与请求不自动重放。


## 候选 16：取消来源与首 token 阶段诊断
